# Detection contract

`mcptop` correlates two local, read-only data sources:

1. configured stdio MCP commands from supported coding-agent configuration files;
2. one operating-system process snapshot from `ps`.

It does not inspect network traffic, agent transcripts, shell history, open files, or process memory.

## Correlation

A process is a direct match when its executable and distinctive configured command tokens match a local MCP entry. Generic launcher words such as `node`, `python`, `npx`, `server`, and `stdio` are not sufficient by themselves.

Children of a direct match are included and carry `inherited_from_pid` in JSON. This makes launcher trees such as `npx -> node` visible without pretending every child independently matched configuration.

Supported client ancestors are detected from executable identity and known application paths for Codex, Claude Code, Cursor, and OpenCode. Merely containing a client name in an argument does not make a process an AI-client ancestor.

## Statuses

### `identified`

The process matches a configured MCP command but does not meet the detached heuristic. Terminal output renders this as `ATTACHED` when a live supported client ancestor is present.

`identified` is not a health verdict. A live desktop client can still retain too many old server processes.

### `suspicious_detached`

The process matches a configured MCP command and either:

- has no supported AI-client ancestor and is at least `--detached-after` seconds old; or
- has an operating-system process state beginning with `Z`.

The default threshold is 900 seconds. A manually launched server can satisfy this heuristic, so `mcptop` never calls it a confirmed orphan and never offers an automatic kill operation.

## JSON schema v1

Top-level fields:

| Field | Type | Meaning |
| --- | --- | --- |
| `schema_version` | integer | Currently `1` |
| `generated_at` | ISO-8601 string | UTC snapshot timestamp |
| `platform` | string | Python platform identifier |
| `read_only` | boolean | Always `true` in v1 |
| `configured_servers` | integer | Parsed local MCP entries |
| `detached_after_seconds` | integer | Applied heuristic threshold |
| `processes` | array | Correlated process observations |
| `config_problems` | array | Safe parser diagnostics |

Each process contains PID, PPID, CPU percentage, RSS bytes, elapsed seconds, process state, status, matched clients and servers, redacted command summary, configuration sources, ancestor evidence, and reasons.

New optional fields may be added in schema v1. Existing fields will not change type or meaning without a schema-version increment.

## Known limitations

- Wrapper tools can rewrite a command so completely that no distinctive configured token remains, producing a false negative.
- A server reparented to a legitimate supervisor may be impossible to distinguish from an intentional daemon.
- A leaked server can retain a live AI-client ancestor and remain `identified`.
- Configuration paths and formats can change between client releases.
- CPU is a point-in-time `ps` measurement; it is not a sampled average generated by `mcptop`.
- RSS semantics differ slightly between operating systems.

These limitations are why every result exposes its evidence and why v1 is read-only.
